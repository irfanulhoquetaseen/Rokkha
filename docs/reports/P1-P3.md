# Report: P1 – P3 (24 Nov 2026)

Live: https://web-production-3fb89dc8.up.railway.app · Repo: https://github.com/irfanulhoquetaseen/jibonsetu · Deployed commit: `983eb6a` (auto-deployed from `main`).

## What was built
**P1: data, constraints, seed, auth**
- Full Prisma schema for every CLAUDE.md entity, plus `Hospital.liveDataEnabled/phone/division/district/address` and `BloodCompatibility`.
- Raw-SQL defences:
  - stock bounds CHECK (`0 ≤ available ≤ total`)
  - partial unique index for one active hold per (user, resource type)
  - requirement target XOR
  - quantity > 0
  - coordinate bounds
- Idempotent seed:
  - 25 fictional hospitals: 17 in Dhaka (all 8 areas), 3 in Chattogram, 5 in Rajshahi including Godagari/Tanore/Puthia; 5 are directory-only.
  - 26 resource types, 8 conditions with CRITICAL/PREFERRED requirements, and the 27-row red-cell compatibility matrix.
  - Stock variety for demos: last-unit rows (Dhanmondi ICU, Karnaphuli ICU, Tanore antivenom), sold-out rows, 4 stale hospitals, specialists off duty.
  - 6 demo accounts, with passwords taken from env only.
- First-aid guides for all 8 conditions in bn and en:
  - Written in our own words from the IFRC International First Aid Guidelines 2020 (page-anchored links) and WHO fact sheets (dengue, snakebite, rabies).
  - Every point is mapped to its source in code comments, with `reviewStatus = SOURCE_CHECKED`.
  - A reviewer re-fetched the sources and verified fidelity, and fixed a trauma/spinal-injury positioning conflict.
- Auth (our own implementation):
  - bcryptjs with a 72-byte guard; DB sessions that store only the SHA-256 of a 256-bit token.
  - httpOnly / SameSite=Lax / Secure cookie; rotation on login and signup; server-side logout.
  - Rate limiting per phone and per IP (right-most `X-Forwarded-For` hop; tunable via env).
  - Origin check on every mutation; one bilingual error shape.
  - Guards return 404 (never 403) and audit `AUTHZ_DENIED`; full audit log for signup, login, failed login and logout.
  - UI: `/signup`, `/login` and logout with BD phone validation (`01[3-9]` + 8 digits) and bn/en messages, including the duplicate-phone error.

**P2: Hospital Resource Console (staff)**
- `/staff` → the staff member's own hospital. Resources are grouped; countable ones have +/− and Set, status ones have switches, and there is search plus low-stock/stale filters.
- Every change is a version compare-and-set. A stale version returns 409 `CONFLICT` with the current values, and the UI shows "Another staff member changed this" with Reload / Re-apply.
- Each change writes a `STOCK_CHANGE` audit entry (old → new) in the same transaction.
- `proxy.ts` returns real HTTP 307 / 404 statuses, so hospital B is a true 404 for staff of hospital A.
- The reservation queue was moved to P4 as instructed; no dead buttons.

**P3: Emergency Finder, matching, first aid, directory**
- Pure matching engine:
  - CRITICAL/PREFERRED weighting; blood resolved by recipient group (unknown group → O− only).
  - Stale (> 30 min) penalty and Haversine distance.
  - Output: score 0–100, rank, and bn/en ✅/⚠️/❌ reasons.
  - Not-suitable hospitals are listed last, with reasons.
- Public Finder (no login):
  - Home page with 8 condition buttons and Call 999.
  - `/find` with blood group, area or GPS, radius, govt/private, free only, resource, and sort (score/distance/freshness).
  - Pagination, notices for invalid input, and an empty state that suggests widening the radius.
- First-aid card: do's, don'ts, Call 999, source link and disclaimer. A full page at `/first-aid/[condition]` returns a real 404 for unknown codes.
- "Unverified — call before going" directory section.
- Bilingual error boundary with Retry and Call 999.
- Finder first-load JS is about 138 KB gzipped (budget 150 KB).

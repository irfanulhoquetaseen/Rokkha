# P1 Data Model, Constraints, Seed, Auth & Roles — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full domain schema with DB-level defenses, an idempotent realistic seed (incl. sourced first-aid guides), and a self-built auth system (sessions, guards, audit) with signup/login/logout UI.

**Architecture:** Prisma 7 schema + one raw-SQL migration for CHECK/partial-unique constraints. Shared `src/lib` (errors, i18n, zod schemas) and `src/server/{auth,audit,http}` modules used by every later phase. Route handlers wrap logic in `apiHandler` for one error shape.

**Tech Stack:** Next.js 16.4 (App Router, `cacheComponents: true`), Prisma 7.10 (`@/generated/prisma/client`, adapter-pg), Zod 4, bcryptjs, Vitest 5 (projects `unit` / `integration`), Playwright.

**Spec:** `CLAUDE.md` (sections 1, 3.1 constraints, 5, 6, 7, 8) + `docs/PLAN.md` P1.

## Global Constraints
- TypeScript strict; Zod on every server input; never trust role/hospitalId/userId from the client.
- Error body everywhere: `{ error: { code, message: { bn, en }, details? } }`; codes/statuses: VALIDATION_ERROR 400, UNAUTHENTICATED 401, NOT_FOUND 404, CONFLICT 409, SOLD_OUT 409, INVALID_TRANSITION 409, LIMIT_REACHED 409, RATE_LIMITED 429, INTERNAL 500. No stack traces to clients.
- Other users'/hospitals' resources → 404 (never 403).
- Session cookie `jibonsetu_session`: httpOnly, SameSite=Lax, Secure in production, Path=/, 7-day expiry; DB stores only SHA-256 of the token; login rotates (old session deleted); logout deletes server-side.
- Mutating API routes check `Origin` matches the request host.
- Bangladeshi phone: `^01[3-9]\d{8}$` after normalizing (strip spaces/dashes; `+880`/`880` prefix → `0`).
- Integration tests use ONLY `DATABASE_URL_TEST` (guarded, name ends `_test`); call `resetDb()` from `tests/support/db.ts` in `beforeEach`. Never mock Prisma.
- Next 16 with `cacheComponents: true`: route handlers that read DB/cookies call `await connection()` (from `next/server`) first; pages/components reading `cookies()`/DB must sit inside `<Suspense>`. Dynamic `params`/`searchParams` are Promises. Read `node_modules/next/dist/docs/` for any Next API you're unsure of.
- Windows-compatible npm scripts. Never commit `.env` or passwords.
- Commit after each task (conventional commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). Do not push.

## Review Focus
- Seed re-run on a live DB with existing reservations/stock → must not duplicate rows or crash; stock untouched unless `SEED_RESET_STOCK=1`.
- Login with phone typed as `+880 17-1111-1111` → normalizes and works.
- Expired session cookie presented → treated as logged out (and row deleted), not a 500.
- Signup with an already-registered phone (incl. differently formatted) → 409 CONFLICT with bn+en message.
- Many failed logins → 429 RATE_LIMITED with `retryAfterSec`, and failures audited.
